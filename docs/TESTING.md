# 测试步骤与已知问题

## 当前已知问题

`Car.h` 按作者现用代码保留：声明了未实现的 `AllForward()`，而 `Car.c` 中已有的 `AllBackward()` 尚未在头文件声明。当前默认main未调用它们；后续接入动作时再完善声明，公开整理不替作者改写代码。

1. `main.c` 是初始化与 OLED 显示基线，没有运动控制入口，蓝牙及传感器尚未实现。
2. `Rightturn()` 设置 M1/M2 为 70、M3/M4 为 40；`Leftturn()` 相反。结合源码的左右轮注释，实际转向与函数名可能不一致，需要用车头方向和实物轮位确认后再改代码。
3. 前进档位为 60、80、100，后退为 50，均为固定占空比设定，尚未标定起转值和轮间差异，也没有闭环测速。
4. 动作切换没有换向等待或斜坡；方向函数和占空比的调用次序仍需结合驱动与电流测试审查。
5. `Stop()` 只把四路比较值清零，并更新 OLED，没有控制 STBY 或主动清方向；停止模式和滑行距离需实测。
6. OLED 文本更新没有统一清除旧字段，数字从三位变两位、方向从 `None` 变单字符时可能留尾字；显示字段不是车轮实时速度。
7. 没有命令超时停车、错误恢复、测距超时或模式切换处理。不能把当前工程接入无人看管的自动运行场景。

## 逐阶段测试

| 阶段 | 操作 | 保存的结果 |
| --- | --- | --- |
| 默认初始化 | 不改 main，重建并下载 | 启动显示、四路 PWM 和方向初值、实物停止现象 |
| 单通道 | 每次只启用一组方向和 PWM，从保守设定开始 | M 编号、主控脚、驱动 A/B、实际轮位和前后方向 |
| 基础动作 | 在测试分支中逐项调用停止、前进、后退和转向 | 同版本接线、调用顺序、实际动作及异常 |
| 蓝牙 | 驱动写完后测试单字节或所选协议及无效输入 | 串口参数、手机发送内容、响应与超时停止 |
| 传感器 | 先分别测试舵机与固定测距，再停车扫描 | 角度校准、目标真实距离、有效值、无回波与超时 |
| 整车避障 | 低速受控空间，含左右受阻和无效测距 | 状态变化、停车现象、失败案例和可重复视频 |

先架空确认单轮再落地；每次只改一个参数或模块。上电静止、主动停止和超时停止分别测试。硬件测试不能由编译输出或函数名称代替。
