# 后续模块开发路线

先把现有电机基础工程变成可以复现的基线，再逐步加入通信和感知。以下均为计划，不表示功能已完成，不预设完成日期。

## 分阶段推进

| 顺序 | 工作 | 验收后才写入成果的内容 |
| --- | --- | --- |
| 1 电机基线 | 核对四路 PWM、轮序与方向，接入受控测试入口，实测停止，修复转向和显示问题 | 同一固件与接线下，四轮各动作和停止可重复演示 |
| 2 蓝牙遥控 | USART1 收发，记录 HC-05 参数，确定简单指令格式；无效输入不得触发新动作；补有效命令超时停车 | 手机输入、动作与停止一一对应，超时及异常输入测试有记录 |
| 3 SG90 | 独立定时器输出，单独校准中位和保守左右范围 | 能重复回中，不顶死，不引起主控复位 |
| 4 HC-SR04 | 固定方向测回波，使用超时与有效标志；记录实测目标距离 | 正常距离、无回波及异常脉宽分别有可解释结果 |
| 5 停车扫描 | 舵机到位并稳定后测左中右，每个距离保留方向与时间 | 三个方向数据不混用，扫描结束回中 |
| 6 简单避障 | 前方近障停车，扫描选路，短时低速转向，回中复测；手动停止可随时中止 | 前方障碍、左右差异、两侧受阻和测距无效场景可重复 |
| 7 按需优化 | 编码器测速与 PID、循迹或电量采集按实际需求选一项 | 新增硬件及资源明确，性能提升有前后对比数据 |

低速避障前先完成有效命令超时、停止优先与传感器失效处理。不依赖一次旧测距持续运动；未安装后向传感器时不默认加入自动倒车。没有编码器或姿态反馈，定时转向不等于准确转过某一角度。

## 模块边界

保持现有 `Hardware` 和 `User` 结构，新增模块只承担清晰的一件事：

- 蓝牙接收提供命令数据，避免在中断里显示 OLED、等待机械动作或直接组织整车运动。
- 电机层负责方向与 PWM，整车层统一决定本次动作；遥控与避障通过模式选择进入同一输出位置，停止优先。
- 舵机层负责目标位置，测距层返回距离、有效状态及测量时间，避障层决定什么时候扫描和移动。
- 主循环以后按时间戳调度动作；长延时会阻塞停止命令，先用简单状态机解决实际需要，再考虑 RTOS。

不提前搭建空接口、通用消息总线或完整导航系统。需要加入传感器时再实现对应代码和最小验证。

## 资源管理

候选脚位见 [硬件表](HARDWARE.md)。TIM2 保持四电机用途，舵机不复用它的计数周期；USART1 避开 PA2/PA3。后续编码器也需要定时器，不能在未盘点前承诺四轮独立测速。新增模块前先更新表，避免功能各自可用、组合后冲突。

## 保存版本与更新材料

初始公开版本保留为电机基础源码。每个模块使用一个功能分支，验证后合并并在 `CHANGELOG.md` 记录版本、接线和测试结果；不要只上传新 HEX 覆盖旧源码。README 的已完成功能与简历只随实际验收更新。

简历当前只写四路 PWM、方向控制、动作函数和持续开发；蓝牙接入、舵机测距与避障保留在计划中。后续按“功能、实现方式、验收结果”补充，不因新增空文件就增加完成项。
